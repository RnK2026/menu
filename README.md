# RnK · 오늘의 식탁

GitHub Pages에서 동작하는 반응형 식단 안내 사이트입니다. Google Apps Script를 연결하면 관리자 비밀번호로 즉시 식단을 저장할 수 있습니다. 외부 라이브러리 설치는 필요하지 않습니다.

## 기능
- 모스크바 시간 기준 현재/다음 식사 두 개 표시, 1분마다 갱신
- 주간 조식·중식·석식 조회, 이전/다음 주 이동, 인쇄
- 7일 날짜 자동 생성, 셀별 편집, 엑셀 3행 × 7열 붙여넣기 (셀 내부 줄바꿈 지원)
- 브라우저 임시 저장, 미리보기, JSON 백업·가져오기
- 서버 비밀번호 검증, 저장 충돌 감지, 다크 모드
- 메뉴·숙소 VoC 공개 게시판, 누구나 답글 작성, 작성자 비밀번호 삭제, 관리자 복수 삭제, 숙소 사진 첨부 파일명 확인

## 1. Google Apps Script 연결 (최초 한 번)
1. https://script.google.com 에서 새 프로젝트를 만듭니다.
2. `apps-script/Code.gs` 내용을 편집기의 Code.gs에 붙여넣습니다.
3. 프로젝트 설정 → 스크립트 속성에 `ADMIN_PASSWORD`를 추가하고 8자 이상의 비밀번호를 직접 설정합니다. 비밀번호를 저장소나 config.json에 넣지 마세요.
4. 여러 명에게 VoC 알림을 보내려면 스크립트 속성에 `VOC_NOTIFY_EMAILS`를 추가하고 주소를 쉼표로 구분해 입력합니다. 예: `admin1@example.com,admin2@example.com,admin3@example.com`. 선택 속성 `VOC_NOTIFY_SITE_URL`에는 게시판 링크의 기준 주소를 입력할 수 있습니다.
5. 편집기에서 `setup` 함수를 선택해 실행하고 Google Drive 권한을 승인합니다. 내 드라이브에 전용 `rnk-meal-data.json` 파일이 만들어지고 파일 ID가 스크립트 속성에 저장됩니다. 재실행해도 기존 파일을 초기화하지 않습니다.
6. 배포 → 새 배포 → 웹 앱: 실행 사용자는 **나**, 액세스 권한은 **모든 사용자**로 설정하고 배포합니다. 조직 계정 정책으로 익명 웹 앱이 금지되어 있으면 허용되는 계정 또는 다른 백엔드가 필요합니다.
7. `/exec`로 끝나는 웹 앱 URL을 `config.json`의 `apiUrl`에 입력합니다. 관리자 비밀번호와 메일 수신자 주소는 입력하지 않습니다.
8. config.json을 커밋하고 푸시하면 자동 배포됩니다. 사이트의 메뉴 관리에서 식단 입력 → 비밀번호 입력 → 공개 저장으로 운영합니다.

공개 API는 식단과 VoC 게시글·답글·사진을 제공합니다. 관리자로 답글을 작성하거나 게시글을 삭제할 때는 서버에서 관리자 비밀번호를 검증합니다. 원본 Drive 파일과 첨부 사진은 공개 공유하지 않아도 되며 웹 앱을 통해 표시됩니다. 비밀번호를 웹 브라우저에 저장하지 않으며, 미리보기/임시 저장은 공개 데이터를 수정하지 않습니다. 새 식단은 빈 상태로 시작합니다. 참고 사이트의 실제 식단을 가져오지 않습니다.

코드를 수정한 경우 Apps Script의 배포 관리에서 기존 배포를 새 버전으로 업데이트하세요. 단순 편집기 저장만으로 기존 웹 앱에 반영되지 않습니다. VoC 기능을 추가한 뒤에는 저장소의 최신 `apps-script/Code.gs` 전체를 편집기에 다시 붙여넣고 기존 배포를 새 버전으로 업데이트해야 합니다. 기존 식단 데이터는 유지되며 `voc` 항목은 자동으로 추가됩니다. Google Apps Script/Drive 사용량 제한이 적용됩니다. 인터넷 공개 비밀번호 API이므로 강한 전용 비밀번호를 사용하세요.

VoC 게시글과 답글은 모두 공개됩니다. 새 게시글과 일반 답글에는 4~50자의 삭제 비밀번호가 필요하며, 작성자는 해당 비밀번호로 자신이 작성한 항목을 삭제할 수 있습니다. `관리자로 작성`을 선택하면 `ADMIN_PASSWORD` 검증을 통과해야 하고 답글에 관리자 표시가 붙으며, 관리자 비밀번호로 그 답글을 삭제할 수 있습니다. 관리자는 관리자 화면에서 게시글을 하나 또는 여러 개 선택해 답글과 첨부 사진까지 함께 삭제할 수 있습니다. 기존 게시글과 답글은 변경 없이 보존되며, 새 삭제 비밀번호가 없으므로 관리자만 삭제할 수 있습니다. 숙소 사진을 선택하면 등록 전에 파일명이 표시되고, 브라우저에서 긴 변 1600px, 약 950KB 이하로 압축한 뒤 Drive 파일로 저장합니다. 반복 등록 방지, 게시글 최대 500건, 게시글별 답글 최대 200건 보관이 적용됩니다.

`VOC_NOTIFY_EMAILS`가 설정되어 있으면 메뉴·숙소 VoC의 게시글과 답글이 등록될 때 작성자가 일반 사용자이거나 관리자여도 모든 수신자에게 알림 메일을 보냅니다. 메일 제목과 본문에는 게시판 종류, 작성자, 등록일시, 제목, 내용, 첨부 사진 유무, 게시판 확인 링크가 포함됩니다. 메일 발송에 실패해도 이미 저장된 게시글이나 답글은 취소되지 않습니다. 메일 권한은 사이트 방문자가 승인하는 것이 아니라 Apps Script 소유자가 편집기에서 `authorizeMail` 함수를 한 번 실행해 승인합니다. 권한 승인 후 웹 앱 배포를 새 버전으로 업데이트하세요.

## 2. GitHub Pages 설정
저장소 Settings → Pages → Build and deployment → Source를 **GitHub Actions**로 선택합니다. main 브랜치에 푸시하면 `.github/workflows/pages.yml`이 테스트 후 정적 파일만 배포합니다.

예상 주소: https://rnk2026.github.io/menu/

Apps Script를 아직 연결하지 않은 경우 data/menu.json을 읽습니다. JSON 백업을 이 파일로 교체하는 정적 운영도 가능합니다. Apps Script 연결 후에는 서버 데이터가 우선합니다.

## 로컬 확인
Node.js 18 이상 및 Python 3 사용:

```sh
npm test
npm run check
npm run dev
```

http://127.0.0.1:4173 에서 확인합니다. file://로 열지 마세요.

식사 시간은 조식 07:30–08:30, 중식 12:30–13:30, 석식 18:30–19:30이며 모스크바 시간을 기준으로 합니다. 주간 메뉴는 월요일부터 일요일까지 표시됩니다. 서버에 예전 시간이 저장되어 있어도 사이트에서 새 시간을 적용하고, 다음 메뉴 저장 시 서버 데이터에도 반영됩니다.

JSON 가져오기는 파일의 첫 날짜부터 7일을 현재 입력표에 불러옵니다. 저장하면 해당 7일만 공개 데이터에 병합하며 다른 날짜는 유지합니다. 동시에 다른 관리자가 저장한 경우 덮어쓰지 않고 새로고침을 요청합니다.

## 두 서비스의 공통 소스와 별도 배포

공통 원본 저장소는 `RnK2026/menu`입니다. 기존 사이트는 https://rnk2026.github.io/menu/ 이고, 대림 사이트는 별도 배포 저장소 `RnK2026/daerim`의 https://rnk2026.github.io/daerim/ 입니다.

- `app.js`, `core.js`, `index.html`, `style.css`: 두 서비스가 공유하는 식단 화면·편집·계산 코드입니다. 메뉴 기능은 여기서 수정합니다.
- `voc-app.js`, `voc.js`: 기존 RnK에서만 사용하는 VoC 기능입니다. 대림 빌드에는 포함하지 않습니다.
- `service.js`: 서비스 식별자와 조식 기본값 등 공통 설정 처리입니다. 빌드 시 대림 설정을 주입합니다.
- `services/daerim/extension.js`: 대림 전용 기능을 추가할 진입점입니다.
- `config.json`, `data/menu.json`: 기존 RnK의 서버 주소와 정적 식단입니다.
- `services/daerim/config.json`, `services/daerim/menu.json`: 대림만 사용하는 서버 주소와 정적 식단입니다. 기존 메뉴와 독립적입니다.
- `apps-script/shared/Meal.gs`: 공통 서버 식단 검증·초기 식단·비밀번호 비교 코드입니다.
- `apps-script/templates/`: 각 서비스의 서버 처리 코드입니다. 수정 후 `npm run build`로 붙여넣기용 `Code.gs`와 `Daerim.gs`를 생성합니다. 생성 파일을 직접 수정하지 마세요.

`npm run build`는 `_site/rnk/`, `_site/daerim/` 두 사이트를 만듭니다. `node scripts/serve.mjs` 실행 후 http://127.0.0.1:4173/rnk/ 와 http://127.0.0.1:4173/daerim/ 에서 확인할 수 있습니다. `npm test`는 대림 기본 조식·데이터 분리·VoC 제외와 기존 기능을 검사합니다.

RnK는 main 푸시 시 자동 배포됩니다. 대림 저장소에는 `deployments/daerim-pages.yml`을 `.github/workflows/pages.yml`로 두며, 공통 저장소 main을 가져와 테스트·빌드·배포합니다. 15분 간격으로 변경을 확인하고 이전 배포와 소스 커밋이 같으면 빌드와 배포를 생략합니다. GitHub 예약 실행은 지연되거나 비활성화될 수 있으므로 즉시 반영하려면 대림 저장소 Actions에서 Run workflow를 실행하세요. 배포 워크플로 자체를 수정했을 때는 대림 배포 저장소에도 해당 파일을 반영해야 합니다.

## 대림 저장 서버 연결 (최초 한 번)

대림 저장 서버 URL은 `services/daerim/config.json`에 연결되어 있습니다. 새 서버를 만들거나 교체할 때는 아래 절차를 따릅니다. 서버 미연결 상태에서도 식단 입력·미리보기·임시 저장·JSON 백업은 사용할 수 있으며, 공개 저장은 서버 연결 후 가능합니다.

1. https://script.google.com 에서 **새 프로젝트**를 만듭니다. 기존 RnK 프로젝트는 그대로 유지합니다.
2. `apps-script/Daerim.gs` 전체를 새 프로젝트의 `Code.gs`에 붙여넣습니다. 이 파일에는 VoC와 메일 기능이 없습니다.
3. 프로젝트 설정 → 스크립트 속성에 대림 전용 `ADMIN_PASSWORD`를 8자 이상으로 설정합니다.
4. `setup` 함수를 실행하고 Drive 권한을 승인합니다. `daerim-meal-data.json` 파일과 `DAERIM_MENU_FILE_ID` 속성이 생성됩니다. 재실행해도 기존 대림 데이터는 유지됩니다.
5. 웹 앱으로 배포합니다. 실행 사용자: 나, 액세스 권한: 모든 사용자.
6. `/exec` URL을 공통 저장소의 `services/daerim/config.json`의 `apiUrl`에 저장하고 커밋·푸시합니다. 기존 RnK의 URL을 넣으면 대림 서버 확인 단계에서 거부됩니다.
7. 대림 사이트에서 공개 저장합니다. 이후 서버 코드 변경은 대림 Apps Script에도 반영하고 기존 배포를 새 버전으로 업데이트합니다. GitHub Pages 배포만으로 Apps Script가 갱신되지는 않습니다.

대림의 빈 조식은 항상 `-`로 채워집니다. 입력표·엑셀 붙여넣기·JSON 가져오기·미리보기·저장에 동일하게 적용됩니다. `-`인 식사는 다음 식사 카드에서 제외되고, 실제 조식 메뉴를 입력한 날은 조식 카드가 표시됩니다. 시간대와 식사 시간은 기존 서비스와 동일한 모스크바 기준입니다. 두 서비스의 브라우저 임시 저장 키도 분리되어 있습니다.

## 한국어 / English 전환과 자동 번역

두 사이트 오른쪽 위의 한국어 / English 버튼으로 화면 전체를 전환합니다. 선택은 브라우저에 기억되며, 같은 브라우저의 두 사이트에서 공유됩니다. 작성자 이름과 사진은 번역하지 않습니다. 작성 중인 입력과 비밀번호는 언어를 바꿔도 유지됩니다.

### 기존 운영 서버 업데이트 (두 프로젝트에서 각각 한 번)

1. RnK Apps Script의 Code.gs를 `apps-script/Code.gs` 전체 내용으로 교체하고 저장합니다.
2. 대림 Apps Script의 Code.gs는 `apps-script/Daerim.gs` 전체 내용으로 교체하고 저장합니다. 각 프로젝트의 기존 스크립트 속성과 데이터 파일 ID는 유지합니다.
3. 각 편집기 위쪽 함수 선택 목록에서 **enableTranslations**를 선택하고 **실행**합니다. Google 권한 요청을 승인합니다. 이 함수가 1분 간격 자동 번역 작업을 설치합니다. 재실행해도 중복 설치하지 않습니다. 기존 setup을 다시 실행할 필요는 없습니다.
4. 각 프로젝트에서 **배포 → 배포 관리 → 수정(연필) → 버전: 새 버전 → 배포**로 기존 웹 앱을 업데이트합니다. 기존 /exec 주소를 유지합니다.

GitHub Pages 업데이트만으로 Apps Script 코드는 변경되지 않습니다. 서버를 업데이트하기 전에는 화면 문구 전환은 동작하지만 입력 내용은 원문으로 표시됩니다.

식단과 RnK VoC 제목·본문·답글은 원문 그대로 보관하고, Google Apps Script LanguageApp으로 한국어·영어 번역을 추가 저장합니다. 기존 데이터도 순차적으로 번역합니다. 한 번에 최대 8개 문구씩 처리하므로 기존 글이 많으면 시간이 걸립니다. 사이트는 1분마다 번역 결과를 갱신합니다. 번역 할당량이나 일시 장애 발생 시 15분 후부터 재시도하며 원문 저장·조회는 계속 가능합니다. 번역 서비스에는 메뉴·제목·본문·답글만 전달하고 비밀번호, 작성자 이름, 사진은 전달하지 않습니다. 사용자가 본문에 적은 내용은 그대로 번역 대상입니다.

번역을 기다리는 내용은 '번역 준비 중 · 원문 표시'로 안내합니다. 번역본에는 '원문 보기'가 붙습니다. 자동 번역은 음식 이름 등에서 부정확할 수 있습니다. 관리자는 식단 입력 칸 아래 **번역 교정**을 펼쳐 한국어·영어 번역을 수정하고 **메뉴 공개 저장**으로 함께 반영할 수 있습니다. 원문을 바꾸면 이전 원문에 대한 교정은 새 메뉴에 적용되지 않습니다. 동일 원문은 같은 번역을 재사용합니다. 교정 칸을 비우고 저장하면 해당 언어를 다시 자동 번역합니다.

미리보기는 공개 데이터를 변경하지 않습니다. 번역되지 않은 입력을 미리 보려면 관리자 비밀번호를 입력한 뒤 미리보기를 누릅니다. 비밀번호가 없거나 번역 서버 연결에 실패하면 원문을 표시합니다. JSON 백업에는 원문과 표시용 번역이 함께 포함됩니다.

번역 공통 코드: `i18n.js`, `messages.js`, `translated-content.js`, `apps-script/shared/Translation.gs`. 서버 코드 변경 후에는 `npm run build`로 붙여넣기용 두 파일을 재생성합니다.


## RnK 차량 VoC

RnK의 `#vehicle-voc`에서 차량 운행·이용 의견을 등록합니다. 공개 게시글, 사진 한 장과 첨부 파일명 표시, 일반·관리자 답글, 작성자 비밀번호 삭제, 관리자 복수 삭제, 한영 전환과 자동 번역, 기존 수신자 알림 메일을 동일하게 사용합니다. 차량 또는 노선과 이용 일시를 적도록 안내합니다. 대림에는 차량 VoC를 포함하지 않습니다.

기존 RnK Apps Script의 Code.gs를 저장소 `apps-script/Code.gs` 전체 내용으로 교체·저장하고, **배포 → 배포 관리 → 연필 → 새 버전 → 배포**를 실행하세요. 기존 스크립트 속성, 데이터 파일 ID, 번역 트리거와 메일 수신자는 그대로 유지합니다. setup 재실행이나 새 저장 파일 생성은 필요하지 않습니다. 서버가 차량 VoC를 지원하기 전에는 차량 등록 버튼만 비활성화되며 기존 메뉴·숙소 게시판은 계속 사용할 수 있습니다. 기존 게시글을 초기화하는 작업은 없습니다.
